# Web SPA (React 19 + TS + Vite, Vitest)

## Layout

- `src/App.tsx` — single-file SPA. Routes: `/`, `/library/:id`,
  `/library/:id/timeline`, `/library/:id/view/:folderId`, `/favorites*`, `/map`, `/admin`.
- `src/api.ts` — **all** REST calls go through here; no `fetch` elsewhere.
- `src/types.ts` — shared API types (mirror backend `domain` JSON).
- `src/styles.css` — all styles.
- `src/i18n.ts` (engine + language tables), `src/i18n-messages.ts` (messages,
  server errors, "%s" templates), `src/i18n-ui.ts` (UI labels/tooltips/templates).
- `src/walking.ts`, trajectories, POI — map helpers with their own tests.
- `src/generated-version.ts` is generated by `scripts/write-version.mjs`; never edit/commit.

## Rules

- Never run `npm test` / `npm run build` by hand — `sh deploy/start.sh local-build`
  runs them in the image build. Then follow the `update-ui-after-build` skill.
- **Canonical strings are English in source**; tests and e2e assert English.
  Translation happens at render time by DOM rewriting. Any new visible text,
  tooltip, `aria-label`, confirm dialog or error must get a row with all 14
  translations (order: ua, de, nl, fi, sv, pl, che, slo, hu, es, it, sl, no, pt).
  Use the `add-ui-text` skill.
- Never write JSX text next to a value (`<p>Imported {n} items</p>`): it renders as
  separate text nodes the translator can't match. Build one string
  (``{`Imported ${n} items`}``) and add a `%s` template row.
  `src/i18n-source.test.ts` fails the build on such labels.
- `window.confirm` goes through `translateMessage`; form/dialog errors use the
  shared `ErrorPopup` toast stack (auto-close 10 s) — never `alert()`.
- Filters that matter for navigation live in the URL (e.g. `kind=` comma list,
  `gps=`), so the viewer and Back keep them.
- A stale tab must not save with old code: the "new version — Reload" banner
  logic must stay intact.
- Videos leaving the viewer must be paused and have `src` removed + `load()`ed
  so the browser stops streaming.
- Dialogs that edit stored entities re-read the entity on open; lists reload
  after save/close (never write back stale state).
- Every behaviour change gets a test in `src/App.test.tsx` (or the focused
  `*.test.ts`), and a line in `docs/requirements.md`.
